DocQuery – Product Requirements Document (PRD)1. Product OverviewDocQuery is an Intelligent Document Chat Assistant that enables users to upload PDF documents and query them using natural language. The system uses Retrieval-Augmented Generation (RAG) to provide accurate, citation-backed answers grounded in document content.2. Goals & Objectives- Enable semantic question answering over uploaded documents- Provide citation-backed, grounded responses- Achieve ≥80% Precision@5 retrieval relevance- Build a modular, production-ready full-stack system3. Target Users- Students and researchers- Knowledge workers- Enterprises handling large document repositories4. Functional RequirementsFrontend:- Upload PDF documents- Chat-based query interface- Display answers with citationsBackend:- Document ingestion and parsing- Layout-aware chunking- Embedding generation- Vector-based retrieval (FAISS)- RAG-based answer generation5. Non-Functional Requirements- Low latency retrieval- Modular architecture- Scalable ingestion pipeline- Transparent answer grounding6. System ArchitectureFrontend: ReactBackend: FastAPIVector DB: FAISSEmbeddings: Sentence-TransformersLLM: API-based (abstracted)Metadata DB: SQLite/Postgres7. Implementation PhasesPhase 1: Setup & PlanningPhase 2: Backend SkeletonPhase 3: Document IngestionPhase 4: Embeddings & FAISSPhase 5: RAG PipelinePhase 6: Frontend IntegrationPhase 7: Evaluation & Optimization8. Evaluation Metrics- Precision@5 for retrieval relevance- Manual relevance annotation- Qualitative answer correctness9. Risks & Mitigation- Hallucinations → Evidence-based retrieval- Poor chunking → Layout-aware strategy- API cost → Local embeddings10. Deliverables- Working web application- Evaluation report- Dissertation documentation
